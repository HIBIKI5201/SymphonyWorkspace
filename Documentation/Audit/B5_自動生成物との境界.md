# B5. 自動生成物との境界

**指摘なし。**

`AGENTS.md` §3 / §7 が定める自動生成物の扱いと、実装側の依存関係を確認した。

## 自動生成物の一覧

| パス | 生成元 | 型の可視性 |
| --- | --- | --- |
| `Assets/Scripts/SymphonyFrameWork/*Enum.cs` | `EnumGenerator` / `AutoEnumGenerator` | `public`（利用側が使う） |
| `Assets/Scripts/SymphonyFrameWork/SymphonyFrameWork.Enum.asmdef` | `AssemblyGenerator` | – |
| `Assets/Resources/SymphonyFrameWork/*.asset` | `SymphonyConfigManager.AllConfigCheck()` | `internal` |

**いずれもワークスペース側（`Assets/Scripts/` `Assets/Resources/`）に生成される。**
パッケージ（submodule）の中には生成物が入らない構成になっており、境界が明確である。

## 確認したこと

### 生成コードの中身に依存した実装が無い

`SceneListEnum` / `TagsEnum` / `LayersEnum` / `AudioGroupTypeEnum` は
**利用側プロジェクトの内容によって中身が変わる**。
パッケージ本体が特定のenum値（`SceneListEnum.NewScene` など）を
literal で参照していれば、利用側で必ず壊れる。

**該当は0件だった。** パッケージ側はenum型を型引数・パラメータとして扱うのみで、
特定の値を前提にしていない。

### 設定アセットの型が `internal` に保たれている

`SceneLoadConfig` / `AudioConfig` / `SaveDataConfig` はいずれも
`Runtime/Configs/Internal/` 配下の `internal` 型である。

**利用側のコードから参照できないため、Inspector と Project Settings 経由でのみ設定できる。**
`AGENTS.md` §3 の記述どおりの状態が保たれている。

これは意図的な設計で、設定の読み書き経路を1つに絞ることで
「コードから書き換えた値がProject Settingsの表示と食い違う」事故を防いでいる。

### asmdef参照の自動注入が壊れていない

`AGENTS.md` §4 は
「`SymphonyFrameWork.asmdef` の `SymphonyFrameWork.Enum` への参照は
`PackageInitializer` がEditor起動時に自動で注入する。
submodule に asmdef の差分が出ても手で戻さないこと」と定めている。

現在の `SymphonyFrameWork.asmdef` は GUID 参照を4件持っており、
うち1件が自動注入されたものにあたる。
**submodule のワーキングツリーは clean（`7b0fa91`）であり、
意図しない差分は出ていない。**

### 生成物が手編集されていない

`Assets/Scripts/SymphonyFrameWork/` と `Assets/Resources/SymphonyFrameWork/` は
本監査の対象外（パッケージではなくワークスペース側）だが、
`AGENTS.md` §7 が禁じる手編集の痕跡が無いかを併せて確認した。
**生成ヘッダが残っており、手を入れた形跡は無い。**

## 確認できていないこと

**再生成による破壊は、実際に再生成しないと分からない。**
`AutoEnumGenerator` を実行して生成物が変化したときに、
パッケージ側のコンパイルが通り続けるかは本監査では検証していない。

**`Documentation/CONTRIBUTING.md` §4 へ「自動生成物の再生成」節を追加した。**

```text
Symphony Administrator > AutoEnumGenerator から3種のenumを再生成
uloop-compile        （エラー0・警告0）
uloop-run-tests      （EditMode / PlayMode）
```

自動生成物を持つフレームワークにとって、「再生成しても壊れない」は
継続的に守るべき性質である。**この検証はワークスペースでは省略されがちで、
省略すると違反が検出できない。** ワークスペースの生成物は Build Settings に
登録済みの3シーンから作られており、たまたま参照が解決してしまうためである。
その理由も条文へ書いてある。
