## 既知の表記

`SymphonyFrameWork` の `W` が大文字である点は、
**リポジトリ全体・名前空間・asmdef名・ディレクトリ名で完全に統一されている**。

```text
Assets/SymphonyFrameWork/          ディレクトリ
SymphonyFrameWork.asmdef           アセンブリ
namespace SymphonyFrameWork        名前空間
"displayName": "Symphony Framework"  package.json の表示名（スペース区切り）
```

一般的な英語表記は "Framework" だが、**統一されている以上これは表記ゆれではなく
このプロジェクトの固有名詞である。** 変更すると名前空間・asmdef・GUID参照へ
広範囲に影響するため、**指摘しない**。

`package.json` の `name` は `symphonyframework`（全小文字）だが、
これはUPMの命名規則に従ったものである。

## 命名規則への適合

`Documentation/CodeGuidelines.md` の「命名規則」節と照合した。

| 対象 | 規約 | 適合 |
| --- | --- | --- |
| 定数 | SCREAMING_SNAKE_CASE | `SYMPHONY_FRAMEWORK`、`DEFAULT_LOCATE_TYPE` — 適合 |
| privateフィールド | `_` 始まりのcamelCase | `_loadedActions`、`_textToDisplay` — 適合 |
| インターフェース | `I` 始まり | 8件すべて適合 |
| enum | `*Enum` 接尾辞 | `LogKindEnum`、`SceneLoadStateEnum`、`LocateTypeEnum` — 適合 |
| DTO | `*Dto` 接尾辞 | `SceneLoadDto`、`PauseDto`、`SaveDataDto` — 適合 |

### 意図的な規約からの逸脱が1件

[IGameObject](../../Assets/SymphonyFrameWork/Runtime/Interface/IGameObject.cs) の
`gameObject` / `transform` が小文字始まりである。

**MonoBehaviour のメンバー名と一致させて、MonoBehaviour が暗黙にこの契約を満たすようにするため**であり、
機能上必要な逸脱である。指摘しない（→ [14](14_KISS原則とYAGNI.md)）。

**ただしXMLドキュメントにその理由が書かれていない。** 1行足せば、
次回の監査とコードレビューで毎回検討しなくて済む。

```csharp
/// <summary>
///     GameObjectを所有するUnityオブジェクトの共通参照を公開する。
/// </summary>
/// <remarks>
///     メンバー名がPascalCaseでないのは、MonoBehaviourの同名メンバーが
///     この契約を暗黙に満たすようにするためである。
/// </remarks>
public interface IGameObject
```

## XMLドキュメントの記述品質

`public` メンバー327件すべてにXMLドキュメントが付いている（→ [B7](B7_XMLドキュメントの網羅.md)）。
記述の質についても数十件を抽出して確認したが、
**型名の言い換えで終わっているものは見つからなかった**。

特に良い例として、判断の理由まで書かれているものがある。

```csharp
// SymphonyAwaitable.cs:10-14
/// <summary>
///     UnityのAwaitableに、完了済み値、合成、条件待機、タイムアウト、Taskブリッジを提供する。
///     WhenAnyは未完了側のAwaitableと例外を安全に消費する一般契約を定められないため、
///     具体的な利用要件が生じるまで提供しない。
/// </summary>
```

```csharp
// SaveDataEntryInfo.cs:26-30
/// <summary>
///     永続化データを読み込み済みかどうか。
///     <see cref="Data" />が存在することは読み込み済みであることを意味しない。
///     キャッシュは初回アクセス時に既定値で作られるため、両者は別の状態である。
/// </summary>
```

**「何をするか」ではなく「なぜそうなっているか」「何を意味しないか」が書かれている。**
このレベルの記述が公開APIに揃っているのは、この観点における明確な強みである。
