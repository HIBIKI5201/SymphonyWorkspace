## 検証したが問題が無かった項目

### Runtime での `System.Linq` は1箇所のみ

**場所**: [AudioService.cs:3](../../Assets/SymphonyFrameWork/Runtime/System/Audio/Internal/Application/AudioService.cs)

`AudioService` はオーディオグループの初期化時に一度だけLINQを通す。
毎フレーム経路ではないため、指摘としない。

`Docs/RuntimeAudit` ではゲーム側のLINQ使用が `6.Composition` の3ファイルに
限定されていることを強みとして挙げていた。**当フレームワークはさらに厳しく1ファイルである。**

### ループ内で不変値を再取得している箇所は見つからなかった

`SceneLoadService.WaitForAll`（[530-560行](../../Assets/SymphonyFrameWork/Runtime/System/SceneLoader/Internal/Application/SceneLoadService.cs)）は
進捗の集約ループを持つが、`progresses.Length` / `tasks.Length` を
`for` の条件で参照しているだけで、ループ内での再計算は無い。

```csharp
for (int i = 0; i < progresses.Length; i++)
{
    totalProgress += progresses[i];
}
```

**配列に対する `.Length` はJITが境界チェックごと最適化するため、これで正しい。**

### 文字列によるシェーダプロパティ／アニメーションパラメータの解決は0件

フレームワークはレンダリングとアニメーションに関与しないため、該当が無い。
