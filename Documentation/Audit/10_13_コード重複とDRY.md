# 10 / 13. コード重複・過剰抽象化とDRY

構造の重複（コピペ）と、**知識の重複**（コードの見た目が違っても同じ判断が複数箇所にある）の
両方を確認した。

## 調査サマリ

| 分類 | 件数 |
| --- | --- |
| 大規模なコピペ重複（数百行規模） | **0** |
| 知識の重複 | 2 |
| 過剰抽象化（1箇所でしか使わない抽象） | 0 |

`Docs/RuntimeAudit` ではゲーム側にEnemy系とBoss系の全面コピペ（約1,300行）があり

## 【設計指摘】既定の猶予フレーム数が3箇所に重複している

**場所**: [SymphonyLocateObject.cs:48](../../Assets/SymphonyFrameWork/Runtime/Component/SymphonyLocateObject.cs)、
[ServiceLocator.cs:345,405](../../Assets/SymphonyFrameWork/Runtime/System/ServiceLocator/ServiceLocator.cs)

`grace = 120` という**同じ知識**が3箇所に literal で置かれている。
片方だけ変更すると、同じ機能の別入口で既定の待機時間が食い違う。

詳細と修正方針は [09](09_マジックナンバーと定数化.md) に記載している。

## 【設計指摘】ロード完了callbackの取り出しが3箇所に重複している

**場所**: [SceneLoadService.cs:154](../../Assets/SymphonyFrameWork/Runtime/System/SceneLoader/Internal/Application/SceneLoadService.cs)、
[SceneLoadService.cs:170](../../Assets/SymphonyFrameWork/Runtime/System/SceneLoader/Internal/Application/SceneLoadService.cs)、
[SceneLoadService.cs:228](../../Assets/SymphonyFrameWork/Runtime/System/SceneLoader/Internal/Application/SceneLoadService.cs)

```csharp
_registry.TakeLoadedAction(request.SceneName)?.Invoke();
```

`LoadScene()` の3つの完了経路（即時完了・非同期完了・既ロード）に同じ1行が現れる。

**1行の重複そのものは軽微だが、「ロード完了時に必ずやること」が
分岐ごとに書かれている構造が問題である。** 4つ目の完了経路を追加したときに
書き忘れても、コンパイルは通り、テストが無ければ気づけない。

**修正方針**: `InvokeLoadedActions(SceneLoadRequest request)` として切り出す。
`internal` メソッドなので破壊的変更にはならない。

[16 SOLID](16_SOLID原則.md) の `LoadScene()` 91行という指摘と同じ箇所であり、
**この切り出しは行数削減にもなる**。

---

## 検証したが問題が無かった項目

### 対称な処理が正しく共通化されている

`SceneLoadService` の `LoadScene()` / `UnloadScene()`、
`ServiceLocateRegistry` の `RegisterWaitingAction` / `UnregisterWaitingAction` など、
対になる処理はいずれも**片方をコピーして符号を変えた形にはなっていない**。

`Docs/RuntimeAudit` が「同じ問題に対して正しい実装と誤った実装が並存している」を
主要な問題としていたのに対し、当フレームワークは**正しい実装のほうが多数派で、
例外が数箇所ある**という構図になっている。

### `GetHashCode` の8実装は「揃った重複」

8つの値型が同じ `(hash * 397) ^ ...` の形を持つ。これは重複だが、
**C#が構造体の等価性実装を言語機能として提供していない以上、避けられない**。
`record struct` へ移行すれば消せるが、`readonly ref struct` として
GCを避けている型もあるため一律には適用できない。**指摘しない。**

### 過剰抽象化は見つからなかった

`Runtime/Interface/` は3ファイルのみで、いずれも利用側が実装する契約である。
`Docs/RuntimeAudit` がゲーム側で指摘した「interface 135件の棚卸し」に相当する問題は無い
（→ [14](14_KISS原則とYAGNI.md)）。

投機的な拡張点（使われていない仮想メソッド、到達しない分岐）も見つからなかった。
