# 07. 外部依存の妥当性

ゲーム側監査の「ライブラリ未活用」を反転させた観点。フレームワークは利用側へ依存を強制するため、
**増やす側ではなく減らす側**で見る。

## 調査サマリ

`Assets/SymphonyFrameWork/package.json` の `dependencies` は2件のみ。

| 依存 | 宣言バージョン | ワークスペース実バージョン |
| --- | --- | --- |
| `com.unity.nuget.newtonsoft-json` | 3.2.1 | 3.2.2 |
| `com.unity.addressables` | **1.21.19** | **2.9.1** |

**依存が2件しかないのは強みである。** R3・VContainer・LitMotion・DOTweenといった
ワークスペースに入っているライブラリは、いずれもパッケージ本体からは参照されていない。

---

## 【確定】`addressables` の宣言バージョンと検証バージョンが乖離している

**場所**: [package.json](../../Assets/SymphonyFrameWork/package.json)

```json
"dependencies": {
  "com.unity.nuget.newtonsoft-json": "3.2.1",
  "com.unity.addressables": "1.21.19"
}
```

**開発と検証は Addressables 2.9.1 で行われているが、パッケージは 1.21.19 を要求している。**

Addressables 1.x と 2.x はメジャーバージョンが異なり、API に破壊的変更がある
（`AsyncOperationHandle` の扱い、`AddressableAssetSettings` の構成など）。

### 何が起きるか

UPMは宣言された最小バージョンを満たせばよいため、**Addressables 1.21.19 の利用側プロジェクトへ
このパッケージが導入されうる**。その環境は一度もコンパイル・テストされていない。

Addressables を使っているのは
[SymphonyVisualElement](../../Assets/SymphonyFrameWork/Runtime/Utility/SymphonyVisualElement.cs) の
UXMLロード経路（[90行付近](../../Assets/SymphonyFrameWork/Runtime/Utility/SymphonyVisualElement.cs)）である。
ここが 1.x で動く保証は無い。

`newtonsoft-json` の 3.2.1 と 3.2.2 はパッチ差なので実害は無い。

### 修正方針

次のいずれか。**どちらを選ぶかは利用者層の判断であり、監査では決められない。**

1. **`"com.unity.addressables": "2.9.1"` へ引き上げる**（推奨）— 実際に検証している構成と一致する。
   Addressables 1.x を使う利用側は導入できなくなるが、
   **動くか分からない状態で導入できるより安全である**
2. 1.x を意図して支えるなら、**1.x 環境でのコンパイルとテストを検証手順へ加える**

**バージョンを上げるのは利用側から見て要求の追加であり、SemVer上はマイナー以上の変更にあたる。**
`CHANGELOG.md` へ明記すること。

## 【設計指摘】`unity` フィールドの下限が実際より低い

**場所**: [package.json](../../Assets/SymphonyFrameWork/package.json)

```json
"unity": "6000.0"
```

ワークスペースは Unity 6000.3.10f1 である。`Awaitable` 系APIや
UI Toolkit の一部は 6000.0 と 6000.3 で挙動が異なる可能性がある。

上と同じ理屈で、**6000.0 での動作は一度も検証されていない**。
ただしAddressablesと違いメジャーバージョンは同じであり、
Unityのマイナーアップデートは後方互換を保つ方針なので、リスクは低い。

**修正方針**: 指摘というより記録である。6000.0 を支える意図があるなら
`CONTRIBUTING.md` の検証手順へ、無いなら `unity` を実バージョンへ寄せる。

## 検証したが問題が無かった項目

- **`asmdef` の `references` に未使用の参照は見つからなかった。**
  `SymphonyFrameWork.asmdef` は Addressables / ResourceManager / Enum / Core への
  4参照のみで、いずれも実際に使われている
- **Unity標準機能で置換できる自前実装は見つからなかった。**
  `SymphonyAwaitable` は Unity 6 の `Awaitable` を**土台として拡張**しており、
  再実装ではない。`ReactiveProperty` は R3 に相当するが、
  **R3への依存を避けるための意図的な自前実装**であり、
  `Documentation/Designs/ReactiveProperty.md` に判断が残っている
- **`SymphonyTween` は DOTween を参照していない。**
  ワークスペースには DOTween が入っているが、パッケージ本体は
  `Awaitable` ベースの自前実装で完結している
