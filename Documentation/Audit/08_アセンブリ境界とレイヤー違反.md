## 【設計指摘】`SymphonyConstant` が Core から `UnityEditor` を参照している

**場所**: [SymphonyConstant.cs:22](../../Assets/SymphonyFrameWork/Core/SymphonyConstant.cs)

```csharp
#if UNITY_EDITOR
    /// <summary>
    ///     Frameworkが実際に配置されている絶対パス（実ファイルパス）を取得する。
    ///     UPM経由（Library/PackageCache等）とAssets直置きの両方に対応する。
    /// </summary>
    public static string GetFrameworkAbsolutePath()
    {
        var packageInfo = UnityEditor.PackageManager.PackageInfo
            .FindForAssembly(typeof(SymphonyConstant).Assembly);
        // ...
    }
#endif
```

`Documentation/CONTRIBUTING.md` は
**「Runtime／Core から `UnityEditor` への参照は `#if UNITY_EDITOR` で囲んであっても違反」**
と定めている。これはその唯一の例外である。

### なぜ違反として扱うか

`#if UNITY_EDITOR` はコンパイル対象からは外れるので、**ビルドは壊れない**。
それでも規約が禁じているのは次の理由による。

- Runtime アセンブリのソースを読むだけでは、Editor専用APIへの依存が見えにくい
- 同じ書き方を他の箇所へ広げると、`#endif` の付け忘れ1つでビルドが壊れる
- 依存方向が図と食い違う（Core が最下層のはずなのに Editor 機能を知っている）

### なぜここに書かれているか

`GetFrameworkAbsolutePath()` は**パッケージの実ファイルパスを解決する**もので、
`PackageManager.PackageInfo` を使わずに UPM 配下と `Assets/` 直置きの両方へ
対応する手段が無い。Editor でしか意味を持たない情報である。

**つまり実装としては妥当で、置き場所だけが規約と食い違っている。**

### 修正方針

`Core/Editor/` へ移す。**同じディレクトリに
[EditorSymphonyConstant.cs](../../Assets/SymphonyFrameWork/Core/Editor/EditorSymphonyConstant.cs) が既にあり、
Editor専用の定数を置く場所として機能している。** ここへ移せば `#if` が不要になり、
依存方向も図どおりになる。

**`public static` メソッドの移動は破壊的変更にあたる。**
名前空間が変わる場合はさらに影響が大きい。次のいずれかを選ぶ。

1. `EditorSymphonyConstant` へ移し、`SymphonyConstant` 側は `[Obsolete]` で1バージョン残す
2. 規約側に例外を明記する（`CONTRIBUTING.md` へ「パッケージパス解決のみ例外」と書く）

**2を選ぶのも正当な判断である。** 1件のために破壊的変更を出す価値があるかは、
利用者への影響次第で決まる。
